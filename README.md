# Lanhu Asset Exporter

`lanhu_asset_exporter` is a Ratatui application that exports a Lanhu project's Sketch JSON, previews,
and development assets into a local, AI-agent-friendly directory. Paste a copied
`/api/project/images` curl request, choose the export mode and target platform, then use the generated
artifacts to recreate UI with Flutter or native iOS.

The pasted curl is parsed as text only; it is never executed as a shell command.

## Requirements

- Rust stable toolchain with Cargo
- Access to the target Lanhu project in a browser

## Run

```sh
cargo run --release
```

Copy the browser request for `https://lanhuapp.com/api/project/images?...`, start the application, and
paste it into the first panel. The terminal is cleared on startup and the completed output directory
opens in Finder on macOS.

## Controls

| Key | Action |
| --- | --- |
| `Tab` | Move between curl input, asset mode, version mode, and target platform |
| `Left` / `Right` | Change the selected mode |
| `Enter` | Start export from any panel |
| `Ctrl+U` | Clear the pasted curl |
| `Esc` | Exit |

The curl body is not shown after paste; the interface displays only its character count. Exports run up
to `min(available CPU cores, 6)` page pipelines concurrently. Request credentials stay in memory and are
never written to manifests, reports, or logs.

## Asset Modes

- **Lanhu cutouts**: default mode; only downloads `image.imageUrl` from `exportable: true` layers,
  then generates PNG `1x`, `@2x`, and `@3x` variants from each original. This most closely matches
  Lanhu's iOS PNG cutout download and excludes system/decorative layers.
- **Reconstruction assets**: downloads all explicit SVG and PNG resources to support visual page recreation.
- **Full layers**: adds Lanhu `ddsImage` layer renderings, including non-exportable layers, for visual auditing.

## Platform Integration

- **iOS**: generates `integrations/ios/Assets.xcassets` and an `asset_map.json` mapping design assets to
  Xcode resource names.
- **Flutter**: generates resolution-aware resources in `integrations/flutter/assets/lanhu`, plus an
  `asset_map.json` and `pubspec_assets.yaml` snippet.
- Platform packages contain assets generated by the Lanhu cutout mode. Other asset modes remain available
  under each page's `assets/` directory for visual reconstruction.

## Export Quality Report

Each export root includes `EXPORT_REPORT.md` for AI/code agents and `export_report.json` for tools. They
summarize page, version, asset, and variant totals; pages with no selected cutouts; missing previews;
download failures; and PNG sources whose effective resolution is below the logical design size at 3x.
Read `EXPORT_REPORT.md` before using `manifest.json`: a generated `@3x` file may be resized from a source
that is not natively 3x.

## Output Layout

```text
lanhu_export/<project>/
├── AI_HANDOFF.md
├── EXPORT_REPORT.md
├── export_report.json
├── manifest.json
├── failures.json                 # only when a page could not be exported
├── integrations/
│   ├── flutter/                  # selected when target includes Flutter
│   └── ios/                      # selected when target includes iOS
└── pages/<page>-<id>/versions/<version>/
    ├── sketch.json
    ├── preview.png               # when Lanhu provides a preview
    └── assets/
```

For an AI-assisted implementation, read `AI_HANDOFF.md`, then `EXPORT_REPORT.md`, and finally
`manifest.json` before opening an individual page's `sketch.json`. Use the Sketch JSON for logical
geometry and native UI reconstruction; use `preview.png` only for visual validation.

## Scope and Limitations

- Supports copied Lanhu project-list curl requests on `lanhuapp.com` subdomains only.
- The tool relies on the authenticated request supplied by the user; expired cookies or insufficient
  project permission will cause export failures.
- It exports design data and resources. It does not infer business behavior, navigation, API contracts,
  or animation timing.
- Respect the access permissions and intellectual-property rights that apply to every exported project.
